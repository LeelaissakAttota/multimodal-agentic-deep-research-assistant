# Security Policy

## Reporting a vulnerability

Use GitHub's private vulnerability-reporting or security-advisory flow for this repository when available. Do not place credentials, exploit payloads containing real secrets, or sensitive research data in a public issue. If a credential may have been exposed, revoke and rotate it before sharing a sanitized report.

Include the affected version or commit, the impacted boundary, reproduction steps using synthetic data, and the expected security property. See `SECURITY_GUIDELINES.md` for the project's threat controls and secure-development requirements.

## Supported release

The current `main` branch is the supported Phase 7 release line. Provider integrations remain abstractions; the mandatory suite and bundled demo perform no live network or paid-model calls.
